# SAMOSA-Bench

The auditor's report card.

SAMOSA-Bench is the measurement companion to the Cookbook and the ledger:
one list of probes, drawn from the measured corpora, run against the
engine and — eventually — against language models. It answers two questions
separately and never conflates them.

## What is here today (v0, 2026-11-14)

- **137 probes**, a projection of the measured corpora, nothing invented:
  - 94 true claims — every identity in `corpus/cookbook/identities.ts`,
    which must come back `ok` (or abstain, never `wrong`);
  - 43 plausible-but-false claims — the false friends in
    `corpus/false-friends.ts`, which may never come back `ok`.
- **The engine baseline**, `bench/report.json`, regenerated by
  `pnpm bench:samosa`: how many true claims the engine verifies, how many
  false friends it catches, how many it abstains on. Abstention is honest
  and is printed, never hidden.
- **The scorer for the model arm**, `pnpm bench:score -- answers.jsonl
  [--model name]`: reads a JSONL of model answers (one line per probe:
  `{"id": "...", "output": "ok" | "wrong"}`), and prints precision,
  recall, accuracy and abstention, side by side with SAMOSA's own verdict
  on the same probes. Unparseable answers are abstentions, never a guess.
- A structural test in `tests/bench.test.ts` keeps the probe list healthy
  (unique ids, both buckets non-empty, every probe engine-addressable).

Gates (same two the launch gates enforce):

1. A Cookbook identity may never come back `wrong` or a shape error.
2. A false friend may never come back `ok`.

`pnpm bench:samosa` exits 1 if either gate fails.

## What is not here (and why)

**No model outputs. No human labels. No precision/recall numbers for any
LLM.** The roadmap (§7.2) calls for answers from three LLMs and a human
label pass per step. This repository contains neither, and this document
claims neither. Producing and shipping invented numbers would be worse
than an empty seat.

To finish the arm honestly, in order:

1. Pick three models and freeze their ids and dates.
2. For each of the 137 probes, prompt each model with:

   ```
   Given the declarations below and the derivation step, answer with
   exactly one word: ok or wrong.

   Declarations: <decls>

   Step: <latex>
   ```

   and save the raw completion as `{"id": "<probe id>", "output": "..."}`,
   one JSONL per model, under `bench/answers/` (gitignored until the
   numbers are final).
3. Score each file with `pnpm bench:score`. Report per-model precision,
   recall, accuracy and abstention next to SAMOSA's own column.
4. For step-level (not claim-level) scoring, extend the probes to
   multi-step derivations and add the human label pass the roadmap calls
   for. That is a larger dataset and a separate review.

## Why the probes come from the corpora

The Cookbook and the ledger are measured: each entry has an expected
verdict enforced in CI. Deriving SAMOSA-Bench from them means the
benchmark can never drift from what SAMOSA was built and tested to do, and
it can never be padded with easy wins. When the corpora grow, regenerate
the baseline and commit the updated `bench/report.json`.

## Layout

| file | what |
|---|---|
| `probes.ts` | the probe list, a projection of the two corpora |
| `samosa-bench.ts` | runs the engine, prints the report card, writes `report.json` |
| `score-answers.ts` | scores a JSONL of model outputs (the v1 arm) |
| `report.json` | the committed baseline; regenerate with `pnpm bench:samosa` |
